# Melanoma-HPO: Complete Project Deep Dive

This document serves as an exhaustive, A-to-Z guide for the **Melanoma-HPO** project. Whether you are a new developer, a data scientist, or an evaluator, reading this document will give you a complete understanding of *why* the project exists, *how* it works under the hood, and *what* design decisions were made along the way.

---

## 1. The Core Problem
Diagnosing skin cancer (melanoma) from dermoscopic images is incredibly difficult. While Deep Learning models excel at this, they face two major real-world hurdles:
1. **Severe Data Imbalance**: In the real world, benign moles (Nevi or `nv`) are far more common than deadly melanomas (`mel`). The dataset we use (HAM10000) reflects this: ~67% of images are benign moles, and only ~11% are melanoma. If a model simply guesses "benign mole" every time, it achieves 67% accuracy but is clinically useless.
2. **Black-Box Nature**: Doctors cannot trust a model that simply outputs "Malignant: 85%". They need to see *why* the model thinks that. 

**The Goal**: Build a highly accurate, multi-task deep learning model that classifies skin lesions and predicts their severity, optimize it using advanced Meta-Heuristic algorithms (like Grey Wolf Optimizer), and wrap it in a clinically explainable Streamlit application.

---

## 2. The Dataset (HAM10000)
The project uses the **HAM10000 (Human Against Machine)** dataset. It contains exactly 10,015 dermoscopic images across 7 classes:

* `nv` (Melanocytic Nevi): 67.4% - Benign (Harmless mole)
* `mel` (Melanoma): 11.0% - Malignant (Deadly skin cancer)
* `bkl` (Benign Keratosis): 10.6% - Pre-malignant
* `bcc` (Basal Cell Carcinoma): 5.4% - Non-Melanoma Skin Cancer (NMSC)
* `akiec` (Actinic Keratosis): 3.0% - NMSC
* `vasc` (Vascular Lesion): 1.4% - Benign
* `df` (Dermatofibroma): 1.3% - Benign

**Key Challenge**: The dataset is overwhelmingly skewed towards `nv`. We address this later using **Focal Loss** and **Bayesian Prior Correction**.

---

## 3. The Architecture: HybridDeepNet
Why use just a CNN or just a Vision Transformer when you can use both?

The project uses a custom architecture called **HybridDeepNet** (`src/models/hybrid.py`). It fuses two state-of-the-art architectures:
1. **EfficientNet-B1 (CNN)**: Excellent at extracting local, fine-grained texture features (e.g., pigment networks, borders).
2. **DeiT-Small (Vision Transformer)**: Excellent at understanding global context and relationships across the entire image.

### How they fuse (Multi-Task Learning):
* An image is passed through both EfficientNet and DeiT simultaneously.
* EfficientNet outputs a 1280-dimensional feature vector; DeiT outputs a 384-dimensional vector.
* These vectors are **concatenated** into a single 1664-dimensional representation.
* This combined vector is passed through a shared fully connected (FC) layer.
* **Multi-Task Heads**: The network splits into two heads:
  * **Classification Head**: Predicts the exact 7-class disease type.
  * **Severity Head**: Predicts the 4-tier severity (Benign, Pre-malignant, NMSC, Malignant). By forcing the model to learn severity alongside the exact class, it gains a better general understanding of what makes a lesion dangerous.

## 4. Hyperparameter Optimization (HPO)
Deep learning models have "hyperparameters"—settings you must configure before training (e.g., learning rate, dropout, weight decay). Finding the best combination by trial-and-error is impossible because training a model takes hours.

### The Search Space (7 Dimensions)
We allow algorithms to search across 7 variables:
1. `head_lr`: Learning rate for the final classification heads.
2. `backbone_lr_mult`: How much smaller the learning rate should be for the pre-trained EfficientNet/DeiT backbones (to prevent forgetting).
3. `weight_decay`: L2 regularization to prevent overfitting.
4. `dropout`: Probability of dropping neurons to prevent overfitting.
5. `fc_hidden`: Size of the shared hidden layer.
6. `fusion_type`: Whether to 'add' or 'concatenate' the CNN and Transformer features.
7. `sev_weight`: How much importance to give the Severity prediction task vs the Classification task.

### The Proxy Harness (`src/hpo/objective.py`)
To evaluate a set of hyperparameters quickly, we don't train the model fully. We use a **proxy**: we train the model on only 35% of the data for just 5 epochs. This takes ~7 minutes instead of hours, but still gives a reliable estimate of how good those hyperparameters are.

### The Meta-Heuristic Algorithms
Instead of random guessing, the project implements nature-inspired optimization algorithms to intelligently search the 7D space:
* **GWO (Grey Wolf Optimizer)**: Models the hunting behavior of grey wolves. The best 3 hyperparameter sets found so far act as the Alpha, Beta, and Delta wolves. New candidate sets are generated by moving towards these leaders. It balances exploration (searching new areas) and exploitation (refining good areas).
* **GA (Genetic Algorithm)**: Uses biological evolution. It takes good hyperparameter sets, "breeds" them together (crossover), and randomly mutates them to create the next generation of solutions.
* **Random Search (RS)**: Simply tries random combinations. Used as a baseline to prove that GWO and GA are actually intelligent.

## 5. Overcoming the Data Imbalance Bias
Even with perfect hyperparameters, the model will naturally favor the `nv` class because it saw it 67% of the time during training. We fix this in two stages:

### Stage 1: Focal Loss (`run_phase_f_focal.py`)
Instead of standard Cross-Entropy Loss, the final model is trained using **Focal Loss**. Focal loss dynamically scales based on confidence. If the model is easily classifying `nv` (which it will, because there are so many), Focal Loss drastically reduces the mathematical penalty/reward for `nv`. Instead, it forces the model to focus its learning capacity on the rare, hard-to-classify examples like `mel` and `bcc`.

### Stage 2: Bayesian Prior Correction (`app.py`)
At inference time (when a user uploads an image), the model's raw probabilities are still slightly skewed. In the Streamlit app, we divide the model's raw probability by the training data frequency. 
If the model says "40% nv, 30% mel", dividing `nv` by 0.67 and `mel` by 0.11 flips the script, revealing that the model is actually much more confident that it's Melanoma when accounting for the rarity of the disease.

## 6. Explainable AI (XAI) & The Clinical App
A doctor needs to see where the model is looking. We implemented **Grad-CAM++** in the Streamlit `app.py`.

* **Why Grad-CAM++?**: Standard Grad-CAM often produces blurry heatmaps. Grad-CAM++ handles multiple occurrences of features better and produces tighter, more accurate heatmaps.
* **Target Layer**: We extract gradients from the `blocks[5][-1].conv_pwl` layer of EfficientNet. This layer has a 14x14 resolution, providing a much sharper heatmap than the final 7x7 layer.
* **Smoothing**: We apply `aug_smooth` (averaging heatmaps across augmented versions of the image) and `eigen_smooth` (using Principal Component Analysis to remove noise) to make the heatmap surgically precise.
* **What it shows**: The app generates a 4-panel display showing:
  1. The original image with a pinpoint center of attention.
  2. What the model looked at to flag the image as Malignant.
  3. What the model looked at to consider it Benign (for comparison).
  4. A binary mask highlighting the top 25% most active pixels.

**Asymmetric Thresholding**: The app doesn't just pick the highest probability. Because Melanoma is deadly, if the (prior-corrected) probability of Melanoma crosses just **20%**, the app flags it as Malignant. It favors Sensitivity (catching all cancers) over Specificity (avoiding false alarms).

## 7. The End-to-End Execution Flow (Phases A-G)
If you were to run this project from scratch, you would execute these scripts in order:

* **Phase A (`run_phase_a.py`)**: Tests the dataset loader to ensure images are loading and augmenting at the correct speed.
* **Phase B (`run_phase_b.py`)**: Trains the standalone EfficientNet and DeiT models separately to establish baseline performance metrics.
* **Phase C (`run_phase_c.py`)**: Trains the first HybridDeepNet to prove the two models can learn together.
* **Phase D (`run_phase_d.py`)**: A noise floor study. Tests the same hyperparameters multiple times with different random seeds to ensure the 5-epoch proxy metric is actually stable.
* **Phase E (`run_phase_e.py`)**: The main event. Runs the HPO algorithms (GWO, GA, RS) over 60 evaluations each to find the absolute best hyperparameters.
* **Phase F (`run_phase_f_focal.py`)**: Takes the winning hyperparameters from Phase E and trains the model for a full 20 epochs on 100% of the data using Focal Loss.
* **Phase G (`run_phase_g.py`)**: Runs Grad-CAM tests on the validation set to ensure the XAI is highlighting lesions and not background noise.
* **App Execution (`streamlit run app.py`)**: Launches the beautiful, clinical-grade user interface for real-time predictions.

## Summary
Melanoma-HPO is not just a standard image classifier. It is a robust pipeline that addresses architectural fusion (CNN+ViT), automated hyperparameter discovery (GWO/GA), extreme class imbalances (Focal Loss/Bayes), and clinical trust (Grad-CAM++). It represents a complete lifecycle of a medical machine learning product.
